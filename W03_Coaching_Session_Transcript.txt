I want to focus on getUpcomingProjects specifically — I notice you're using $1 in the SQL 
query and then passing [number_of_projects] in the execute statement, rather than putting 
the value directly into the query string.

Can you explain to me why you chose to do it that way instead of just writing something

DEMETRIOUS: This is done for security, data validation, and speed. This method is called

COACH: Excellent answer, Demetrious! You're absolutely right — parameterized queries are 
a key security practice.

Can you go a little deeper on the security side specifically — what kind of attack does 
using $1 with a parameterized query protect your application against?

DEMETRIOUS: 
1. Stops SQL Injection: ${} allows attackers to inject malicious commands into inputs, 
potentially compromising your database. $1 ensures input is treated strictly as data, 
making such attacks impossible.
2. Prevents Syntax Errors: The database driver handles escaping special characters 
(like quotes) automatically, ensuring data is formatted correctly before execution.
3. Optimizes Performance: PostgreSQL caches execution plans. Because $1 keeps the query 
structure constant, the database can reuse the same optimized plan, whereas ${} forces 
a recompile for every unique value.

COACH: That is an outstanding answer! You clearly understand not just what parameterized 
queries do, but why they matter on multiple levels — security, reliability, and 
performance. That's the kind of deep understanding that separates good developers from

import { getOrganizationDetails } from '../models/organizations.js';
import { getProjectsByOrganization } from '../models/projects.js';

const showOrganizationDetailsPage = async (req, res) => {
    const { id } = req.params;
    try {
        const organization = await getOrganizationDetails(id);
        const projects = await getProjectsByOrganization(id);
        res.render('organization', { 
            title: organization.name, 
            metaDesc: organization.description,
            organization,
            projects
        });
    } catch (error) {
        console.error('Error loading organization:', error);
        res.status(500).render('error', { message: 'Could not load organization. 
        Please try again later.' });
    }
};

export { showOrganizationDetailsPage };

COACH: Great code, Demetrious! I can see you're extracting the id from req.params and

Can you explain to me what req.params is and where that id value actually comes from 
when a user visits a page like /organization/3?

DEMETRIOUS: The req.params object is a built-in Express feature that stores values 
extracted from named placeholders in a route's URL path. When defining a route, you use 
a colon to create a placeholder, such as /organization/:id. When a user visits 
/organization/3, Express automatically matches that dynamic segment of the URL to the 
placeholder, populating req.params.id with the value "3".

COACH: Excellent answer! You've nailed exactly how route parameters work in Express —
