    const default_role = 'user';
    const query = `
        INSERT INTO users (name, email, password_hash, role_id) 
        VALUES ($1, $2, $3, (SELECT role_id FROM roles WHERE role_name = $4)) 
        RETURNING user_id
    `;
    const queryParams = [name, email, passwordHash, default_role];
    const result = await db.query(query, queryParams);

COACH: Nice work Demetrious! I can see you are using bcrypt to hash the password before saving it, which is exactly the right approach.

Looking at this line specifically:

const salt = await bcrypt.genSalt(10);
const passwordHash = await bcrypt.hash(password, salt);

Can you explain to me in your own words what a salt is and why it is important when hashing passwords?

---------------------------------------------

DEMETRIOUS: A salt is basically a random string of characters that gets added to the password before it is hashed. So even if two users have the exact same password, their hashes will look completely different in the database because each one gets its own unique salt.
The reason this is important is because without a salt, hackers can use something called a rainbow table attack, which is basically a pre-computed list of common passwords and their hashes. If they get access to your database and your passwords are hashed without a salt, they can just look up the hash and find the original password instantly.
By adding a salt, even if someone gets into the database, they cannot use those pre-computed tables because every hash is unique. The 10 I passed into bcrypt.genSalt(10) is called the salt rounds or cost factor, it controls how many times the hashing algorithm runs. The higher the number, the longer it takes to compute, which makes it even harder for someone to brute force the passwords. I chose 10 because it is a good balance between security and performance, it is strong enough to protect users but not so slow that it affects the experience of registering on the site.

const authenticateUser = async (email, password) => {

Now let us move to the third topic. Can you paste in the middleware you wrote that protects routes — specifically the code that checks whether a user is logged in before allowing them to access a page?

---------------------------------------------

DEMETRIOUS:
So I have two middleware that handle this route protection. Every one of them is found in src/controllers/users.js.

The first one is requireLogin which just checks if a user is logged in at all:

const requireLogin = (req, res, next) => {
    if (!req.session || !req.session.user) {
        req.flash('error', 'You must be logged in to access that page.');
        return res.redirect('/login');
    }
    next();
};

It checks if there is a session and if that session has a user object on it. If there is no user it flashes an error message and redirects them straight to the login page. If the user is logged in it calls next() which passes control to the next function in the chain, meaning the actual route handler runs and the user gets access to the page.

The second one is requireRole which goes a step further and checks not just if the user is logged in but what role they have:

const requireRole = (role) => {
    return (req, res, next) => {
        if (!req.session || !req.session.user) {
            req.flash('error', 'You must be logged in to access this page.');
            return res.redirect('/login');
        }
        if (req.session.user.role_name !== role) {
            req.flash('error', 'You do not have permission to access this page.');
            return res.redirect('/');
        }
        next();
    };
};

This one is a function that returns a middleware function, which allows me to pass in the required role dynamically. So in my routes I can use it like this:

router.get('/new-organization', requireRole('admin'), showNewOrganizationForm);

That means only users with the admin role can access that page. Everyone else gets redirected to the home page with an error message. I used this pattern to protect all the admin routes like creating, editing, and deleting organizations, projects, and categories.

---------------------------------------------
